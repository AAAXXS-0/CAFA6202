# 图表分支说明

图表分支只接收赛题已经分好的图表目录，不做自动路由。默认 `auto/ink`
已经正式使用 v6；`projection/yolo` 仅保留为历史对比入口。

## 1. 配置与检测器

配置示例为 `afac_pipeline/table/config.example.json`。检测器有四种模式：

- `auto`：正式默认，使用 v6 密度分表和黑白边界，不加载模型；
- `ink`：显式使用与 `auto` 相同的无模型定位；
- `yolo`：仅用于历史对比，强制使用配置的 YOLO 权重；
- `projection`：仅用于历史对比，使用旧横线投影定位。

正式分表固定使用原图20%分析图，只做左右墨迹晕染，分表方向严格限制为上下方向。横向分表 V2 先找行方向低密度白缝，再合并被窄标题/表头打断的相邻白缝；候选白缝两侧必须分别具有足够高的主体高度和墨迹密度，主体归属相同的候选只记录、不落刀。小残表会在降低高度标准后再复核一次，只有表格密度仍接近主体时才强制切开。切口优先落在合并白缝中最上方的原始白缝，让标题完整归入下面的表。正式流程不再产生左右分表；5%密度图仅保留为审计中间产物。

每张子表再使用1%投影峰值和最低0.05%墨水比例保守取得分析框，并向外留约短边1%的余量。分析框完成后，只从原图子表生成一张50%统一分析图；黑线、行白缝和列白缝全部在这一张图、同一坐标系中完成。灰度225生成的是临时灰度二值图，只用于图像结构分析，不能称为R×C墨迹bool矩阵。

黑线可靠时直接采用黑线。行黑线不可靠时，先擦除已确认的竖线，再根据当前子表墨迹密度自适应决定文字向左右晕染的强度；墨迹比例不超过1%的连续横向白带作为行边界，行白带仍允许只有1像素宽。

列黑线不可靠时，先擦掉已确认的黑横线和黑竖线，再按墨迹密度自适应做上下晕染；随后用高度约18%、步长约5%的纵向窗口扫描。每个窗口从1px开始增加列白缝最小宽度，连续3个阈值得到相同且非零的白缝数量便立即停止。相邻窗口列数最多相差4条、且较少一侧至少80%的列位置能对应时，视为同一表体；最长连续稳定段作为表体，并在整段表体上重新执行一次首稳扫描。若仍没有稳定且非零的列白缝，直接进入fatal error，不再启用旧20%列白带兜底。

行列边界形成可信R×C以后，程序才回到原图，按每个物理格向内缩约10%检查真实墨迹，并生成与物理网格同尺寸的R×C墨迹bool矩阵。true表示该格内部存在墨迹，false表示该格内部为空；它只用于模型空输出、缺行缺列和空格补齐，不参与前面的划线决策。
得到物理横线后，程序把原分析框顶部到第一根横线之间按原图像素单独
裁成顶部候选区，并向上避开4像素线芯。候选区只用灰度225判断是否
确有墨迹；完整条带原样保留供审计，识别时只裁掉四周纯空白，不缩放
文字。非空时单独识别为普通Markdown，最终只放在对应表格前一次，
不参与也不改变预处理确定的R×C物理网格。识别失败只写warning，主体
表格继续处理。
竖线两侧背景的取样距离会随分辨率从20%时的2～3像素扩大到50%时的
5～8像素，避免取样点仍落在变粗后的线芯里面。
完整网格通常至少找到5条黑线，且必须有线位于中部80%区域。程序还有两个
严格例外：其一，若稳定行白带至少12根、数量达到横线的3倍且间距稳定度
达到80%，横线只视为表头/分段线，正式行网格改用白带；其二，两三列小表
不可能凑够5根竖线，此时通过95%覆盖率和灰度对比的少量竖线会吸附分析框
外沿，只要能形成至少两列且没有超大格就采用。若稀疏横线只包住表头和整段
数据，程序保留横线作为硬边界，仅在大间隔内部用行白带细分，避免多行表头
被拆散。

白缝检测统一使用50%分析图。诊断JSON会记录行白缝自适应左右晕染比例，以及每个列滑窗的起止位置、列数、首稳阈值、最终窗口范围和表体框。

整图20%分表预览安全上限为4608px，子表50%统一分析图安全上限为12000px，并且每次只
处理一张已经分开的表。两者都只是内部分析图；请求图仍受3900px上限约束，
但只能通过物理网格切块满足，绝不通过缩小图片满足。

## 3. 切片原则

程序对横向执行“完整跨度 90%”，对纵向执行“中段 95% + 邻域深度差”。
两个方向都保持“黑线优先、白带兜底”。黑线除了数量外还必须通过空间分布
检查，避免把全部挤在左右边缘的线误当成列网格。即使图片尺寸能
整体送入，只要逻辑总格子数超过 `max_logical_cells_per_tile=140`，就沿
完整逻辑行列边界做均衡切块。规划器先找切片最少的方案，再尽量避免少于
80 格的边角碎片；宽高比超过 8:1 时，即使未达 140 格也会沿长边继续拆分。
内部空行、空列和空单元格全部保留，因为它们决定全局对齐位置；默认不重复首行或首列。
任一逻辑格若独占所在方向 95% 以上也判为不可信网格。即使未达到这个比例，
只要某个逻辑行或列本身超过 3900px、无法沿网格落刀，同样按前置错误终止。

黑线模式只把真正达到各自规则的线作为逻辑边界；带 padding 的分析框四边
不再自动伪装成表格线。正式请求图不仅保持原始宽高比，而且保持原始像素
尺寸，禁止任何拉伸或缩小。若没有 R×C 网格，或者沿网格仍切不出最长边
不超过 3900px 的图片，立即报预处理致命错误并保存诊断，不调用模型。

## 4. 本地 OCR 与网格回填

```bash
PYTHONPATH=/tmp/afac_rapidocr python3 main.py run-local-tables \
  --manifest work/tables/dataset_manifest.json \
  --work-dir work/local_ocr \
  --output-csv outputs/table_local_ocr.csv
```

本地模式不会把 OCR 的视觉文字行直接猜成表格。每个请求图先分成约 2000px
的小块，避免把 3900px 表格压小；随后将所有 OCR 文字框从小块坐标映射到
请求图坐标，再映射到原图坐标，最后用 v6 行列边界定位单元格。重复表头和
行名列只作为识别上下文，不会被重复写入。

白带检测可能保留仅用于安全切割的冗余边界。本地后处理会删除整行或整列
完全没有任何 OCR 内容的边界，但保留真实单元格中的空值。最终结果以 HTML
`table/tr/td` 输出，并在 `local_ocr_quality/` 保存回填率和行列统计。

### FireRed-OCR 图表路径

FireRed 仍只实例化一份模型。长图输出上限保持 4096 token，图表单独提高到
8192 token，并使用独立缓存身份，因此调整图表参数不会让已完成的长图缓存
失效。表格的物理结构（总行数、总列数和切片负责范围）以预处理网格为准，
FireRed或API只负责填写单元格内容。每个逻辑格会记录是否存在文字墨迹；
模型省略内部空列或整条空行时，后处理按墨迹顺序补回 `<td></td>`。
模型多出的空行、空列和完全重复的表头会删除并warning；多出的非空结构
不会扩大最终矩阵，而是判为内容异常。

如果预处理确认某个逻辑切片的所有单元格内部都没有文字墨迹，流程会直接
按预处理行列数生成全空 HTML 表并跳过模型。模型正常返回空字符串时，会先
单独退让 3 次；仍为空再使用同一物理行列兜底，结果和原因一并写入 SQLite
缓存，重跑不会再次等待该切片。这里的“空”指正常响应但没有 HTML/Markdown，
与请求过载等临时故障不同。

历史 v12 实测使用同一个 23×24 数字表区域：560 格整块耗时 307.55 秒，但在
8192 token 上限处截断。另一些内容复杂的 192 格和 304 格切片也曾输出超长
且未闭合的 HTML，证明格子数只能作为输出预算，不能代表图片像素大小。
v13 曾使用 280 格输出预算并删除像素兜底块和整表缩放；实际 API 对接近
280 格的复杂块仍可能识别不稳，因此 v18 把正式上限减半为 140 格。
23×24 会均衡拆成四个 23×6 小块，每块138格；8×24 会拆成两个
8×12 小块。
对于列宽极不均匀的细长表，仍按整体宽高比保证最少切片数。规划器保留
80 格优选下限，在降低单次识别压力的同时避免大量边角碎片。

## 6. HTML 聚合、质量检查与失败策略

固定原则只有两句：

```text
物理结构：预处理为准
格子内容：模型为主
```

每个逻辑切片在写入 SQLite 成功缓存前都必须通过质量闸门；读取历史缓存时
也执行同一检查。原始响应保存在 `responses/模型原始/`，归一化后的固定
矩阵保存在 `responses/`。重试和warning始终打印“原图名 / 区域 / 切块名”。

| **预处理没有形成可信 R×C 网格** | 行或列边界缺失 | 写 `预处理致命错误.json` 并停止，不进入模型阶段 | 不涉及缓存 |
| **R×C 网格无法原尺寸切到 3900px 内** | 存在超大逻辑行或列，说明前置网格错误 | 写出最大行高、最大列宽和边界图后停止；禁止缩放或像素切片 | 不涉及缓存 |
| 情况 | 判断与复核 | 最终处理 | SQLite状态 |
|---|---|---|---|
| 顶部候选区判空 | 原图裁片没有足够墨迹 | 不调用模型，不输出标题 | 不写标题缓存 |
| 顶部候选区连续空响应 | 已按后端规则复核仍为空 | 不输出标题，继续主体表格 | 写标题空缓存，避免重复等待 |
| 顶部候选区识别异常 | 请求或模型明确报错 | 写warning并继续主体表格，不改变R×C | 不写标题成功缓存，整图暂不缓存以便下次只重试标题 |
| 正常HTML或Markdown表格 | 可解析，并能映射回预处理 `R×C` | 模型内容填入固定物理矩阵 | 正常成功 |
| 模型少行、少列 | 利用墨迹bool按原顺序寻找缺失空位 | 缺位补 `<td></td>`，总行列不变 | 成功并warning |
| 多出空行、空列、重复表头 | 只删除可以确认没有新增信息的结构 | 清理后映射回固定矩阵 | 成功并warning |
| 多出非空结构或格子膨胀 | 清理后仍超出预处理网格 | 内容异常复核3次；仍失败则该块不完整 | 不写成功缓存 |
| HTML截断、不闭合、多个table、围栏循环 | 质量闸门直接拦截 | 内容异常复核3次；禁止坏响应进入结果 | 不写成功缓存 |
| 提示词回显或纯文字且无法解析 | 找不到可靠表格 | 内容异常复核3次；仍失败则该块不完整 | 不写成功缓存 |
| 请求过载、识别失败、429/5xx、超时 | 请求级临时故障 | 官方客户端换账号平方退让，最多15次 | 耗尽后不写成功缓存 |
| **预处理墨迹bool确认整块为空** | 所有逻辑格内部均无文字墨迹 | **不调用模型，生成同尺寸全空 `R×C` 矩阵** | “预处理确认空” |
| **模型无HTML/Markdown，墨迹bool认为有字** | 本地端首次请求加3次复核；官方端内部完成3次退让 | **仍为空时按约0.1%墨迹误判特例，保留结构、内容置空** | “全空兜底” |
| **模型返回完整但全空的table，墨迹bool认为有字** | 同样复核3次 | **连续全空后生成同尺寸全空矩阵** | “全空兜底” |
| 区域合并发生坐标冲突 | 无法可靠放回全局 | 区域标记不完整；**不再拼损坏原文** | 不写整图缓存 |

这里的“全空矩阵”不是空字符串，也不是 `<table></table>`。例如预处理为
8行×5列，就一定生成真正包含8个 `<tr>`、每行5个空单元格的HTML。墨迹
bool只参与判断“哪里可能有字”，即使它偶尔误判，也不能修改物理行列。

某块请求级退让耗尽后只记录该块，继续同图下一块、下一区域和其他原图。
一张图全部切块尝试完仍有失败，才写入 `recognition_failures.json` 并标记
整图不完整。成功切块缓存全部保留，再次运行只补失败块。批次存在任何不完整
原图时只生成 `partial_results.csv`，不生成正式100行提交CSV。
