# 图表分支说明

图表分支只接收赛题已经分好的图表目录，不做自动路由。默认 `auto/ink`
已经正式使用 v6；`projection/yolo` 仅保留为历史对比入口。

```mermaid

    A["赛题已分好的图表"] --> B["SHA-256 精确复用"]
    B --> C["原图固定缩放至 20% 分析图"]

    D --> E["宽低密度带分开同图异表"]
    E --> F["每张表保守提取分析框，并映射回原图"]

    HR --> V{"该方向黑线是否至少 5 条？"}
```

## 1. 配置与检测器

配置示例为 `afac_pipeline/table/config.example.json`。检测器有四种模式：

- `auto`：正式默认，使用 v6 密度分表和黑白边界，不加载模型；
- `ink`：显式使用与 `auto` 相同的无模型定位；
- `yolo`：仅用于历史对比，强制使用配置的 YOLO 权重；
- `projection`：仅用于历史对比，使用旧横线投影定位。

v6 先把原图固定缩到 20%，再缩到该分析图的 25%，所以密度图固定为原图
5%。分表低密度点上限收紧为 2%，整条分隔带平均墨水上限为 1.5%。
如果下一张表的标题把宽空白带打断，切口固定放在标题上方，使标题归入
下面的表。每张分表再使用 1% 投影峰值和最低 0.05% 墨水比例保守取得
分析框，并向外留约短边 1% 的余量。

内部边界统一使用灰度阈值 225。横线候选在独立二维表格包络内必须至少有
90% 黑像素；竖线忽略包络两端各 5% 的不稳定区，中段至少有 95% 黑像素，
并且灰度均值要比左右邻域至少深 30，避免同列数字“1”的竖笔画被当成表线。
一个方向至少找到 5 条黑线才采用，否则该方向改用墨水比例不超过 1% 的
白带。找横向白带时文字只左右扩张 0.15%，找纵向白带时上下扩张 0.4%，
不再删除靠近分析框外沿的候选。所有检测坐标最终映射回原图，实际请求图
也始终从原图裁切。
赛题最大图固定缩放后最长边为 4455px，因此分析图安全上限设为 4608px；
这只限制内部分析图，不改变大模型或本地 OCR 请求图的 3900px 上限。

## 3. 切片原则

程序对横向执行“完整跨度 90%”，对纵向执行“中段 95% + 邻域深度差”。
两个方向都保持“黑线优先、白带兜底”。即使图片尺寸能
整体送入，只要逻辑总格子数超过 `max_logical_cells_per_tile=280`，就沿
完整逻辑行列边界做均衡切块。规划器先找切片最少的方案，再尽量避免少于
80 格的边角碎片；宽高比超过 8:1 时，即使未达 280 格也会沿长边继续拆分。
内部空行、空列和空单元格全部保留，因为它们决定全局对齐位置；默认不重复首行或首列。

黑线模式只把真正达到各自规则的线作为逻辑边界；带 padding 的分析框四边
不再自动伪装成表格线。所有模型请求图保持原始宽高比，禁止纵向拉伸；
若边界不足才使用带自适应重叠的像素切片。所有请求图最长边不超过 3900px。

## 4. 本地 OCR 与网格回填

```bash
PYTHONPATH=/tmp/afac_rapidocr python3 main.py run-local-tables \
  --manifest work/tables/dataset_manifest.json \
  --work-dir work/local_ocr \
  --output-csv outputs/table_local_ocr.csv
```

本地模式不会把 OCR 的视觉文字行直接猜成表格。每个请求图先分成约 2000px
的小块，避免把 3900px 表格压小；随后将所有 OCR 文字框从小块坐标映射到
请求图坐标，再映射到原图坐标，最后用 v6 行列边界定位单元格。重复表头和
行名列只作为识别上下文，不会被重复写入。

白带检测可能保留仅用于安全切割的冗余边界。本地后处理会删除整行或整列
完全没有任何 OCR 内容的边界，但保留真实单元格中的空值。最终结果以 HTML
`table/tr/td` 输出，并在 `local_ocr_quality/` 保存回填率和行列统计。

### FireRed-OCR 图表路径

FireRed 仍只实例化一份模型。长图输出上限保持 4096 token，图表单独提高到
8192 token，并使用独立缓存身份，因此调整图表参数不会让已完成的长图缓存
失效。表格的物理结构（总行数、总列数和切片负责范围）以预处理网格为准，
FireRed或API只负责填写单元格内容。每个逻辑格会记录是否存在文字墨迹；
模型省略内部空列或整条空行时，后处理按墨迹顺序补回 `<td></td>`。
模型多出的空行、空列和完全重复的表头会删除并warning；多出的非空结构
不会扩大最终矩阵，而是判为内容异常。

如果预处理确认某个逻辑切片的所有单元格内部都没有文字墨迹，流程会直接
按预处理行列数生成全空 HTML 表并跳过模型。模型正常返回空字符串时，会先
单独退让 3 次；仍为空再使用同一物理行列兜底，结果和原因一并写入 SQLite
缓存，重跑不会再次等待该切片。这里的“空”指正常响应但没有 HTML/Markdown，
与请求过载等临时故障不同。

实测使用同一个 23×24 数字表区域：560 格整块耗时 307.55 秒，但在
8192 token 上限处截断。另一些内容复杂的 192 格和 304 格切片也曾输出超长
且未闭合的 HTML，证明格子数只能作为输出预算，不能代表图片像素大小。
全量 49 张唯一图的旧 320 贪心切法生成 1627 个逻辑块，其中 172 块少于
80 格。v12 正式预处理生成 1563 个逻辑块，其中 16 块少于 80 格；另有
29 个无法取得可靠逻辑边界的像素兜底块，总请求图为 1592 张，最大仍为
280 格和 3900px。23×24 会切成两个 23×12；8×24、1679×130px 的极宽块
会切成两个 8×12。对于列宽极不均匀的细长表，还会按整体宽高比保证最少
切片数，不会因为候选都略超 8:1 而退回整表。因此正式值选 280，并通过
均衡切块同时减少模型截断、API 纯文本和请求数量。

## 6. HTML 聚合、质量检查与失败策略

固定原则只有两句：

```text
物理结构：预处理为准
格子内容：模型为主
```

每个逻辑切片在写入 SQLite 成功缓存前都必须通过质量闸门；读取历史缓存时
也执行同一检查。原始响应保存在 `responses/模型原始/`，归一化后的固定
矩阵保存在 `responses/`。重试和warning始终打印“原图名 / 区域 / 切块名”。

| 情况 | 判断与复核 | 最终处理 | SQLite状态 |
|---|---|---|---|
| 正常HTML或Markdown表格 | 可解析，并能映射回预处理 `R×C` | 模型内容填入固定物理矩阵 | 正常成功 |
| 模型少行、少列 | 利用墨迹bool按原顺序寻找缺失空位 | 缺位补 `<td></td>`，总行列不变 | 成功并warning |
| 多出空行、空列、重复表头 | 只删除可以确认没有新增信息的结构 | 清理后映射回固定矩阵 | 成功并warning |
| 多出非空结构或格子膨胀 | 清理后仍超出预处理网格 | 内容异常复核3次；仍失败则该块不完整 | 不写成功缓存 |
| HTML截断、不闭合、多个table、围栏循环 | 质量闸门直接拦截 | 内容异常复核3次；禁止坏响应进入结果 | 不写成功缓存 |
| 提示词回显或纯文字且无法解析 | 找不到可靠表格 | 内容异常复核3次；仍失败则该块不完整 | 不写成功缓存 |
| 请求过载、识别失败、429/5xx、超时 | 请求级临时故障 | 官方客户端换账号平方退让，最多15次 | 耗尽后不写成功缓存 |
| **预处理墨迹bool确认整块为空** | 所有逻辑格内部均无文字墨迹 | **不调用模型，生成同尺寸全空 `R×C` 矩阵** | “预处理确认空” |
| **模型无HTML/Markdown，墨迹bool认为有字** | 本地端首次请求加3次复核；官方端内部完成3次退让 | **仍为空时按约0.1%墨迹误判特例，保留结构、内容置空** | “全空兜底” |
| **模型返回完整但全空的table，墨迹bool认为有字** | 同样复核3次 | **连续全空后生成同尺寸全空矩阵** | “全空兜底” |
| 像素兜底块返回全空 | 没有可靠逻辑行列数 | 不能猜矩阵，记录切块失败 | 不写成功缓存 |
| 区域合并发生坐标冲突 | 无法可靠放回全局 | 区域标记不完整；**不再拼损坏原文** | 不写整图缓存 |

这里的“全空矩阵”不是空字符串，也不是 `<table></table>`。例如预处理为
8行×5列，就一定生成真正包含8个 `<tr>`、每行5个空单元格的HTML。墨迹
bool只参与判断“哪里可能有字”，即使它偶尔误判，也不能修改物理行列。

某块请求级退让耗尽后只记录该块，继续同图下一块、下一区域和其他原图。
一张图全部切块尝试完仍有失败，才写入 `recognition_failures.json` 并标记
整图不完整。成功切块缓存全部保留，再次运行只补失败块。批次存在任何不完整
原图时只生成 `partial_results.csv`，不生成正式100行提交CSV。

像素重叠兜底仍使用Markdown相邻内容去重，因为它没有物理网格；这条路径
不能使用逻辑矩阵兜底。

### 无模型表格外轮廓实验

这个工具可以独立复现“强缩小后的二维墨水密度如何找到完整表格”，不负责内部行列判断：

```bash
python afac_pipeline/table/工具/工具002_墨水区域实验.py \
  --image "待测试图片.jpg" \
  --output-dir "work/验证/无模型墨水定位" \
  --yolo-manifest "原粗流程单图清单.json"
```

输出的 `004_最终墨水轮廓.png` 使用绿色多边形表示墨水外轮廓、红色矩形表示完整外接框；`005_墨水轮廓与YOLO对比.png` 额外使用蓝色矩形表示原 YOLO 表格框。

内部行列的正式优先级固定为：先使用传统横竖表格线；只有确认没有可靠表格线时，才使用行列长空白带。

### 暂存方案

横线和竖线分别使用非等比例分析图的方案暂不实施，设计细节保存在[非等比例缩放方案备忘](./归档/非等比例缩放方案备忘.md)。正式请求图始终保持原始宽高比。
