# 图表V7候选流程

这里集中验证四项改造，暂时不修改正式预处理、FireRed一键脚本和API一键
脚本。所有输出写入 `work/验证/`，不会覆盖正式manifest或SQLite缓存。

## 四项改造对应关系

### ① 行列分别选择黑线、白缝或混合边界

正式V6实际上已经能分别得到“行来源”和“列来源”，所以行黑列白、行白列黑
并非完全缺失。V7在此基础上把每个方向的三套候选全部显式落盘：

- 纯黑线；
- 纯白缝；
- 黑线与白缝合并。

行轴和列轴独立选择。某一方向只有1～4根黑线、同时又有完整白缝时，V7优先
把黑线视为表头/分段硬边界，与白缝合并，而不是要求整个方向只能二选一。

中间图中：红线为黑线候选，蓝线为白缝候选，绿色为最终采用边界。

### ② 稀疏表加强列白缝的行方向晕染

正式V6沿行方向最多扩张到表高的3%。V7保持密集图原强度不变，图像越稀疏，
扩张比例越接近6%，用于抹掉同一列文字、数字内部过于整齐的纵向白缝。

每张表会保存：

- 擦除黑线后的墨迹；
- V7稀疏列晕染；
- 所有滑动窗口；
- 首个稳定宽度和最终列白缝。

### ③ 分表后晕染取得实际分析框

20%横向分表保持不变。每个分表块内部新增一次只服务于“找外框”的二维
墨迹晕染：稀疏表使用更强连接，选择最大主体连通块，并吸收与主体横向重叠、
距离很近的小标题/表头块。内部行列检测仍使用重新从原图裁出的50%图。

旧分析框、新分析框、二值墨迹、晕染图和主体连通块都会保存，方便判断是否
缩框过头或仍带入太多空白。

### ④ 模型优先R×C共识拼接

第二个脚本只读取已经存在的 `responses/模型原始/`，不调用API或本地模型。
预处理R×C和墨迹bool只写入对照表，不再作为强制输出尺寸。

第一版规则故意简单：

- 同一行带的左右切块取最大模型行数，少行块在尾部补空；
- 同一列带的上下切块取最大模型列数，少列块在右侧补空；
- 绝不为了服从预处理R×C裁掉模型非空内容；
- 解析失败块单独记录，其他块继续生成结果。

尾部补空尚不能判断缺失发生在中间还是末尾，因此这是给人看的基线，不是
最终后处理。后续可根据结果增加重叠行名/列名锚点。
