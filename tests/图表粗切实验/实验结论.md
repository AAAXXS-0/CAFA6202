# 图表粗切备用路线：当前实验结论

## 1. 已经排除的方案

### 1.1 纯像素大块

`1829aea8` 用 3200 像素责任区只切成 6 块时，每块实际包含数千个数据格。
API 响应反复在约 11KB～16KB 截断，并出现重复行幻觉。递归切到约
`366×496` 像素仍不能稳定恢复，因为任意二分会切断表格语义。

结论：图像像素尺寸小，不代表模型输出量小；不能用少量大块覆盖密集表。

### 1.2 全局首列/首五列拼图

把不相邻的“左上角 + 表头 + 行名列 + 主体”拼成一张图，对部分块有效，
但在另一些数值区会让左侧合并单元格占据主体，模型再次无限重复。

结论：全局上下文不能作为所有块的固定模板，尤其不适合梯形和大量 rowspan
结构。

### 1.3 失败后继续任意二分

即使主体从四列减到两列，只要仍带全局五列上下文，四个抽查块仍全部截断。

结论：失败反馈必须沿安全线缩小“连续主体”，不能保留一个有害的固定上下文。

## 2. 已经验证有效的部分

### 2.1 安全线小块

复用正式预处理的安全行列线，把每块控制在约 140 个逻辑格。已有 13 份
无上下文响应全部成功，均为 35×4，响应约 2.7KB～3.1KB，无截断、无坏 HTML。

这说明黑线/白缝仍然有价值，但只应负责安全下刀，不应强迫最终输出服从
预处理的 `R×C`。

### 2.2 连续半窗重叠

当前抽查使用：

    首块：安全列 0～8
    相邻块：安全列 4～12

两块共享连续一半画面，不做不相邻区域拼图。四个块 4/4 成功，响应约
1.5KB～3KB，没有截断。

### 2.3 模型结构优先

同一批块中，预处理估计 35×8 或 35×5，模型实际给出 31×3、33×6、
33×6、35×6。这里不能强行拉回预处理列数；模型把部分物理线识别为同一
语义单元，往往比预处理更合理。

### 2.4 缺行补空

第二行带的两个模型矩阵为 33×6 和 35×6。动态对齐识别出两列重叠，
在缺失位置补了 2 行空值，其中包括模型漏掉的年龄 26。横拼结果为 35×10。

这与目标规则一致：模型负责内容和语义结构；某块漏行时，不移动后续数据，
而是在对应位置补空。

## 3. 当前仍有的风险

`1829aea8` 顶部是梯形密表。第一行带中，模型在相邻块里把男女两列数值读成
交错的一列序列。半窗重叠把行对齐相似度从 0.68 提高到 0.84，补空行从
12 降到 4，但内容仍存在错位。

这不是 HTML 解析器或缓存问题，而是模型对该局部几何结构的识别差异。继续
增加规则容易变成针对单图硬编码，因此正式化前需要再用其他图验证：

1. 普通矩形密表是否能稳定识别两列以上重叠；
2. 梯形表是否普遍出现交错列；
3. 对交错列是否值得加入通用的“一列拆两列”检测，还是交给本地 OCR 兜底。

## 4. 推荐的正式方向

建议保留两条路线：

1. 现有精细物理网格路线继续作为高结构约束方案；
2. 新增“安全线粗切 + 连续半窗重叠 + 模型矩阵软对齐”作为预处理 fatal
   或模型结构明显优于物理网格时的备用方案。

备用路线的切块应满足：

- 只沿已检测的安全行列线裁原图，不缩放、不拉伸；
- 不生成最终 R×C 墨迹 bool 矩阵；
- 相邻块保留连续局部重叠，禁止拼接不相邻的全局行头；
- HTML 截断时，只沿当前块内部安全线缩小主体；
- 模型正常返回空白时保留为空，不强造内容；
- 后处理按模型矩阵对齐，缺行补空行、缺列补空列；
- 所有 API 原文、矩阵、拼接审计和 warning 实际落盘。

## 5. 当前状态

本轮仅修改和增加 `tests/图表粗切实验/` 内的实验代码，正式一键脚本和正式
图表预处理没有切换。原因是半窗路线已经可用，但还未达到可直接全量替换的
稳定度。
