# 粗切块相信模型V1：首轮实验结论

## 1. 实验路线

本实验完全跳过黑线、白缝、R×C和墨迹bool矩阵，只使用已经固化的横向分表：

    横向分表 → 像素责任区粗切 → 官方API
    → 模型输出转二维矩阵 → 左右拼列块 → 上下拼行带

初始责任区约3200像素，四周保留256像素重叠。模型输出截断时，只对失败块
自动二分，最多递归3层；不会重切已经成功的块。

## 4. 185a2337结果：绕过fatal，但仍有错列

旧R×C流程无法形成可信网格。粗切路线最终生成三张表：

- 第1表：12×64；
- 第2表：57×137；
- 第3表：57×136。

所有15个父块最终完成，低置信拼接0次，存在2次重叠冲突。为解决模型HTML截断，
实验累计形成47条该图相关缓存，其中包含正常子块以及14个修复父块。

成功处理了三种API异常：

1. 纯文字但列数稳定：恢复成矩阵；
2. 空白块返回官方后台提示词：作为空块忽略；
3. HTML在约1.1万字符处截断：沿长边递归复切，最后一个窄高块改为上下切。

但是第1表存在明显重复列和OCR错位。例如左块尾部与右块头部本应重叠，右块却把
1906.35识别成1903.65、2020.14识别成2201.14，还插入了66633。当前算法只寻找
固定的“左侧尾部K列=右侧头部K列”，因此没有发现这段带插入/删除的重叠，最终
把两段都保留下来。

结果位置：

- work/验证/粗切块相信模型V1/185a2337-c7a0-41f0-a283-a3d8c22a1041/06_最终拼接结果/整张图片最终结果.html
- 失败块自动复切的图片、原文和审计均位于02、03、04目录下的“失败块自动复切”。

## 5. 是否值得继续

值得。原因是：

- d8证明无需物理R×C也能稳定完成二维拼接；
- 185证明旧流程fatal的图片可以得到规整输出；
- 预处理不再因一根黑线或白缝判断错误而整图退出；
- API输出自身提供了可用于对齐的重复内容。

但当前版本还不能直接替换正式流程，主要缺口是“列序列动态对齐”。下一步应将：

    固定K列重叠检测

改为：

    每列生成跨行内容指纹
    → 对相邻列序列做局部动态对齐
    → 允许OCR替换、插入列、漏列
    → 在真正缺失的位置补空列

行方向使用同一算法的转置版本。完成后再测试5b宽表和1829密集表；若两张都通过，
即可考虑把粗切路线接进一键脚本，同时把精细R×C保留为可选旧路线。
